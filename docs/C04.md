# C04 capture integration

Implemented locally on 2026-09-10. No client settings are edited automatically.
C04 adds two `UserPromptSubmit` command adapters. MCP is read-only by default;
[C05](C05.md) adds explicitly enabled draft refinement and CLI review.

## Connect a client

Use an installed Carry interpreter, or the project's editable install. The
settings command pins the interpreter that runs it, so run all examples through
that environment's `carry` executable.

```sh
carry --workspace /path/to/state capture configure --client claude \
  --source records --opt-in-prompts
carry --workspace /path/to/state capture settings --client claude

carry --workspace /path/to/state capture configure --client codex \
  --source records --opt-in-prompts
carry --workspace /path/to/state capture settings --client codex
```

`records` must be a configured writable **personal** source. Whole-prompt capture
is an explicit opt-in: the entire submitted user text is stored with best-effort
masking. Assistant replies, tool outputs, transcripts, working-directory values
and arbitrary hook fields are not persisted. No transcript files are opened.

The settings command prints a JSON fragment. Append its single handler to the
existing `hooks.UserPromptSubmit` list in the selected Claude settings file or
Codex `hooks.json`; retain all unrelated keys and handlers. Keep a backup before
editing. Register this handler only once across active config layers. Do not
also create an independent MCP draft for that event: the hook owns its initial
draft. C05 permits explicit refinement of that same draft using the event ID.

For Codex, review the exact new hook with `/hooks` and trust it using the normal
client flow, then restart the session. A trusted project is also required for
project-local configuration. Unreviewed hooks are skipped, including in
non-interactive execution. No trust bypass is needed. Claude's settings and
organisation policies must also permit the command hook.

Submit a clearly labelled synthetic prompt, then check:

```sh
carry --workspace /path/to/state capture status
carry --workspace /path/to/state status
```

`no_receipt` means configuration exists but no event has been persisted. Only
`captured` or `duplicate`, with event and proposal links and a success timestamp,
prove persistence. A version probe does not prove hook trust or connection.
Status describes the last attempt; it is not a live connection monitor. Index
freshness is reported separately and capture never waits for embeddings.

Pause and resume are per client and take effect for the next hook invocation:

```sh
carry --workspace /path/to/state capture pause --client codex
carry --workspace /path/to/state capture resume --client codex
```

Pause acquires the same bounded writer lock as ingestion. Once it returns,
subsequent hook calls do not even read stdin. An already committed event is kept.
To disconnect, pause first, remove only the generated handler from the selected
settings file, and restart the client. Keep the stored Markdown and receipts;
this operation is not a request to delete history.

## Native contracts and diagnostics

| Client | Capability gate | Identity |
|---|---|---|
| Claude Code | version >= 2.1.196 | client + `session_id` + `prompt_id` |
| Codex CLI | version >= 0.153.4 and `features list` reports hooks enabled | client + `session_id` + `turn_id` |

The Codex gate is a conservative tested baseline, not a claim about the first
release to support hooks. New versions still must send the required fields.
Both adapters require `hook_event_name=UserPromptSubmit` and a nonempty `prompt`.
Identity is a hash of the native identifiers, never the text or wall clock.
Identical wording in different events stays distinct. A replay with different
masked text and the same native identity is refused.

Missing binaries, older versions, disabled hooks, missing event identity,
unsupported events, malformed input and input larger than 256 KiB get an explicit
state and a repair action. A native event without a stable ID is not captured.
The runner returns zero and writes no stdout, including on ingest failure, so
capture cannot block a prompt or inject context. If even a receipt cannot be
written, it emits a fixed, content-free stderr diagnostic. Lock wait is bounded
at three seconds; retry the same native event after a busy writer or disk error.
There is no automatic retry queue.

Contract references, checked during implementation:
[Claude Code hook input](https://code.claude.com/docs/en/hooks#common-input-fields)
and [Codex hook input and trust](https://learn.chatgpt.com/docs/hooks).

## Storage and recovery

- Raw event: `<records_dir>/.events/evt_<hash>.md`. Canonical Markdown, deliberately
  excluded from the normal index walk. It has event identity, UTC timestamp,
  client, masked content digest and the masked prompt.
- Linked proposal: a normal Carry record in `draft` state, with the same event
  link and a source reference to the raw Markdown file. This is a **verbatim
  review candidate**, not a synthesized or accepted decision.
- Receipt: `capture-<client>.json` in the workspace state directory. It contains
  states, timestamps, canonical links, masking categories and safe error types;
  no prompt, native session ID, credentials or exception message.
- Settings/consent: `capture.json` in the workspace state directory. Keep this
  configuration when rebuilding an index; it is not disposable retrieval data.

All cooperating record and capture writers share `records.lock`. Individual
files publish atomically after flushing and syncing their content. The event is
written first, then its draft, then the receipt. If interrupted between these
steps, replay repairs the missing step. Draft identity is recovered from
frontmatter if the event ledger is lost or its publication failed. This is
recoverable multi-file publication, not an all-or-nothing filesystem transaction.
Power-loss durability across directory renames is not asserted.

Imported files are untouched. Acceptance still requires `carry record accept`
with the expected revision, followed by `carry index` (or the existing optional
MCP auto-index setting). These were the C04 boundaries. [C05](C05.md) now
provides client/manual synthesis,
review diffs, explicit targets and accepted-versus-pending retrieval. Its reviewed
correction path commits one file and preserves target files unchanged.

## Verification on this machine

The original 80 tests were rerun before implementation: standard Python passed
79 with the optional SDK test skipped; the project environment passed all 80.
Independent tests then demonstrated six pre-existing failures before their fixes:

1. A 200-character recall budget returned 1,115 characters.
2. Boolean/fractional budgets were accepted.
3. Valid JSON with an invalid RPC shape terminated the MCP process.
4. A crash after record publication but before ledger publication created a
   second record on replay.
5. Review could write to a source subsequently configured read-only.
6. Review followed a records-directory symlink outside the source root.

These now have passing regression tests. Metadata quoting also has a regression
for frontmatter injection and event IDs resembling scalar values.

Native-client validation used an isolated synthetic workspace and an extra
**test-only** wrapper. The real client emitted its event; the wrapper passed it
twice to the unchanged `carry.hook` entry point, inspected receipts, then blocked
that synthetic prompt before model processing. Production Carry never blocks.
Codex's temporary hook was reviewed through its normal `/hooks` interface.

| Actual client | Observed native fields | Result |
|---|---|---|
| Claude Code 2.1.267 | `session_id`, `prompt_id`, `prompt`, `hook_event_name` | one raw event and one linked draft; replay `duplicate`; runner silent |
| Codex CLI 0.153.4 | `session_id`, `turn_id`, `prompt`, `hook_event_name` | one raw event and one linked draft; replay `duplicate`; runner silent |

Both actual clients were then paused and sent a new sentinel prompt. The record
files remained byte-for-byte unchanged and each receipt reported `paused`.
Each native draft was explicitly accepted, indexed, and retrieved with its ID
and citation through a new MCP process. Sanitized evidence is in
[c04-native-verification.json](c04-native-verification.json).

This validates real capture plus fresh MCP retrieval. It does not claim a
model-driven two-client answer-quality evaluation or the full C05 correction
loop. The mixed imported-note correction gap was open at C04; C05 now handles
explicit whole-record targets, as documented in C05.md.

The C04 suite and clean-wheel checks are recorded in its historical handover
addendum; C05.md describes subsequent lifecycle behavior.
No prior Ollama latency measurements were treated as freshly verified.
